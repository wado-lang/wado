# WEP: Geas — Tensor Compilation for Wado

## Context

Wado has no tensor story. The closest thing in the tree is
`example/microgpt.wado`, a scalar autograd graph where every arithmetic
operation allocates a `Value` node. It is a faithful port and a useful GC
benchmark. It is not a foundation for machine learning work.

Four findings from the 2026 literature drive this proposal.
`docs/research-ml-inference-webgpu.md` records the survey they come from.

Compile-time shape checking has become implementable. Dependent and refinement
types both demand proofs to decide type equality, which is why neither was
adopted in practice. Staging replaces the proofs with assertions evaluated as
compile-time computations, and the ECOOP 2026 work validated it on ported
ocaml-torch programs.

Axis notation has converged. The einx bracket notation marks the axes an
operation actually sees, and reads declaratively where `einsum` reads
imperatively. Static checking of it exists only as external stubs, because
Python cannot check it in the language.

Quantization formats are a moving target parameterized by block size, scale
representation, and rotation, not a fixed list of names.

Fusion's objective function is not what it was. On WebGPU at batch size 1,
dispatch count dominates and kernel quality does not. That objective belongs to
the GPU work, and naming it here is what bounds the claims a CPU MVP can make.

Gale is the architectural precedent, and a measured one. Its generated parser
beats hand-written `sqlparser-rs` by 1.12x and tree-sitter's native Rust by
2.19x. Its architecture is a static compiled fast path with escalation to a
runtime tier. This WEP adopts five properties of it:

- The escalation boundary is a decidability result. Gale escalates because the
  lookahead language of a recursive ambiguous prefix is non-regular, so subset
  construction provably does not converge.
- The escalation sites are enumerable and named. Gale's simulator decides
  exactly three parser sites, each pinned by a fixture and visible through
  `gale dump --atn`.
- Cost routes as much as correctness does. Two sites that belong on the
  simulator for correctness stay static because measurement showed 2.6 ms
  becoming 402 ms, and the divergence is pinned rather than hidden.
- An unused mechanism costs nothing. A grammar needing no simulator carries
  none and is byte-for-byte unaffected.
- The runtime is inlined into the generated file, which is what removes
  version drift between generator and runtime.

Version drift is a problem the field has not solved. ONNX opset drift and
checkpoint incompatibility are both drift between a model artifact and the code
that runs it, which is what the last property removes.

Kiln makes the staging available without a language change. Wado has neither
const generics nor general compile-time evaluation, so shapes cannot be carried
as integers in type position. A Kiln generator, however, runs arbitrary Wado at
compile time and emits Wado source, which is staging. Gale already works this
way. Geas is therefore a package, not a language feature.

## Decision

### Name

Geas — in Irish myth, a binding laid on someone that cannot be broken.

The name states the bargain this design makes. A geas is accepted rather than
suffered, and what it buys is power. A model that submits to fixed shapes at
build time gets fused kernels, and gets its shape errors at build time instead
of wrong numbers at run time. The constraint is the mechanism, not a limit on
it.

A short concrete noun, consistent with Gale, Kiln, Jade, and Marl. It leaves
those names' elemental theme, which is already fully occupied.

### A Kiln Generator, Not a Library

Geas is invoked as a Kiln generator over a model artifact:

```wado
use { Model } from "./model.safetensors" with {
    generator: { module: "wado-lang:geas@0.1" },
};
```

A library would place shape checking at run time, where every other framework
already has it. Only a generator can place it early enough for a shape mismatch
to stop the build.

Three properties follow from the choice, and each answers a standing problem in
the field:

- A Kiln generator runs in a full Wasm sandbox. A build-time code generator that
  reads untrusted model files is an obvious attack surface, and both `build.rs`
  and `setup.py` execute with the developer's privileges. Geas cannot.
- The generated module carries its own kernel runtime, inlined as Gale's is.
  There is no separate runtime package to version-match, so opset drift has no
  place to occur.
- The generated module is ordinary Wado. It is readable, debuggable, and
  optimized by the same pipeline as any other Wado source.

### Weights Stay Outside the Generated Module

The generator reads the checkpoint's metadata and never its tensor payloads.
Metadata means axis names, extents, dtypes, and layout. Checkpoints reach
gigabytes and a Wasm module must not.

The generated module therefore contains the typed graph, the kernels, and a
loader that checks the incoming payloads against the shapes the graph was
compiled for. A checkpoint that does not match reports which axis disagreed, at
load time, rather than producing wrong numbers.

A model below an inline threshold may opt into `#include_bytes` instead, which
makes the component self-contained. This is for test fixtures and very small
models, not the normal path.

### Shapes Are Named Axes, Discharged by Staged Computation

An axis has a name rather than a position. Transposition is then a change of
description rather than a movement of data, and an operation states which axes
it consumes.

Axis extents come from two places. A static extent comes from the checkpoint
metadata and is known at stage 0. A dynamic extent, such as sequence length or
batch size, is a named symbol that stage 0 carries through the shape algebra
without knowing its value.

Shape consistency is discharged as compile-time computation, not as proof. This
is the ECOOP 2026 formulation, and Kiln is the stage where it runs.

A shape condition that stage 0 cannot discharge is a compile error. Geas has no
runtime shape check to fall back on, because the MVP has no tier below the
static one. This is the MVP's boundary, stated rather than worked around.

### Operations Are Written in an einx-Shaped Tagged Template

A tagged template gives einx's notation with Wado's type checking behind it,
which is the combination Python cannot reach:

```wado
let y = dot`a [b], [b] c -> a c`(x, w);
```

The brackets mark the axes the operation reduces over. Unbracketed axes are
vectorized. The tag function sees the literal text and the typed holes, so the
notation is checked against the actual tensor types at compile time rather than
by an external stub.

The notation sits above the type layer and does not constrain it.

### The Backend Is a Trait

A `Backend` trait, monomorphized at each use, selects where kernels run. The
MVP ships one implementation: CPU, over `core:simd`.

An effect was considered and set aside. Wado's effects lower through stack
switching, whose per-operation cost is unmeasured here, and a tensor dispatch is
a hot path. A trait's cost is known to be zero.

### The MVP Is Tier 1 Only

Gale's two tiers become three here. This WEP builds the first:

| Tier              | Decided at        | Covers                               |
| ----------------- | ----------------- | ------------------------------------ |
| Static (tier 1)   | build time        | Static shapes, weights, fused blocks |
| Bucketed (tier 2) | first use, cached | Residual sequence and batch extents  |
| Dynamic (tier 3)  | per token         | MoE routing, speculation, early exit |

Tiers 2 and 3 are deliberately absent, not undiscovered.

Tier 2 is a shape-class cache rather than a simulator. Generating a kernel is
expensive where Gale's ATN step is cheap, and the generation must finish before
the dispatch it serves can run. Tier 3 is the genuine analogue of Gale's ATN:
data-dependent control flow that no bucketing covers.

### The Generator Reports Every Fusion Decision

`gale dump` is what makes Gale's escalation auditable, and its absence is why
`torch.compile`'s graph breaks arrive as a mystery. Geas's generator reports,
per operation, what it fused, what it did not, and why.

The MVP has one tier and reports anyway. A declined fusion carries the reason
it was declined, and those reasons are what will route the later tiers.

### What the CPU MVP Cannot Validate

The MVP validates the shape algebra, the generator architecture, the notation,
and the backend seam. It does not validate the fusion objective.

On CPU the objective is memory traffic and SIMD occupancy. On WebGPU at batch
size 1 the objective is dispatch count. They are different objectives, and a
fusion policy tuned against the first is not evidence about the second. The GPU
WEP will have to re-derive its policy from measurement rather than inherit this
one.

## Roadmap

1. The shape algebra. Named axes, static and symbolic extents, and staged
   discharge inside the generator. Finished when a rank or extent mismatch in a
   two-layer MLP is a compile error naming both disagreeing axes.
2. The notation. The einx-shaped tagged template lowering to a Wado loop nest.
   Finished when `dot` and a reduction lower correctly and match a reference
   implementation elementwise.
3. Checkpoint metadata. A safetensors reader in the generator, emitting the
   typed graph. safetensors comes first because its header is JSON over raw
   tensors, with no protobuf and no quantization to model. Finished when a real
   checkpoint's shapes check against a hand-written graph, and a deliberately
   mismatched one names the axis.
4. The backend seam. The `Backend` trait with the CPU/`core:simd`
   implementation. Finished when the MLP from step 1 runs and matches the
   reference within tolerance.
5. The fusion report, following what `gale dump` established. Finished when
   every operation in the step-3 model reports a decision and a reason.
6. End to end. A small real model runs and produces correct output, with a
   `benchmark/` row against llama.cpp's CPU backend on the same weights.
   Finished when the row is in `benchmark/README.md`.

## Known gaps

Tier 2, the bucketed JIT. Residual sequence and batch extents need a
shape-class cache populated on first use. Closing it needs a cache key design, a
warmup story, and an answer to generation latency becoming user-visible. Gale's
generator is 1.40x slower than ANTLR4's, which is free at build time and is not
free at first use.

Tier 3, dynamic dispatch. MoE routing, speculative decoding, and early exit are
data-dependent and no bucketing covers them. Closing it needs the escalation
boundary drawn as a decidability question, as Gale's is, rather than as a
heuristic.

The GPU backend. A second `Backend` implementation over `wasi:webgpu`, with the
fusion objective re-derived for dispatch count. This is a WEP of its own.

Quantization. Block formats are parameterized by block size, scale
representation, and rotation, so the type that carries one must be
parameterized the same way rather than named after a format. GGUF as an input
format arrives with this, not before it.

Training. Geas is an inference design. An autograd layer over the same shape
algebra is plausible and unowned.

Whether the notation survives contact with a real model. Step 2 adopts the
tagged template to measure it. If it reads badly at model scale, replacing it
is a change to one layer.

Whether the backend should be an effect after all. The trait is chosen because
its cost is known to be zero and the effect's is unmeasured. A second backend
makes the measurement possible.
