# WEP: 128-bit Integer Types (i128/u128)

## Context

Wado needs 128-bit integer types for:

1. **Cryptographic operations**: EC cryptography, hash functions, and big-integer arithmetic require 128-bit intermediate results
2. **High-precision timestamps**: Nanosecond timestamps over long periods
3. **Large identifiers**: UUIDs and other 128-bit identifiers

WebAssembly Wide Arithmetic proposal provides native instructions for efficient 128-bit operations:

| Instruction      | Signature                       | Description                       |
| ---------------- | ------------------------------- | --------------------------------- |
| `i64.add128`     | `[i64 i64 i64 i64] → [i64 i64]` | 128-bit addition                  |
| `i64.sub128`     | `[i64 i64 i64 i64] → [i64 i64]` | 128-bit subtraction               |
| `i64.mul_wide_u` | `[i64 i64] → [i64 i64]`         | 64×64→128 unsigned multiplication |
| `i64.mul_wide_s` | `[i64 i64] → [i64 i64]`         | 64×64→128 signed multiplication   |

Division, remainder, shifts, bitwise operations, and comparisons require software implementation.

### Design Alternatives

Two implementation approaches were considered:

1. **Compiler builtin**: Treat i128/u128 as primitive types with special-cased codegen
2. **Struct + operator overloading**: Implement as regular structs using the trait system

## Decision

Implement i128/u128 as **structs with operator overloading**.

### Rationale

1. **Aligns with Wado philosophy**: Minimize hard-coded compiler logic; define builtins in Wado source files
2. **Most operations need software implementation anyway**: Only add/sub/mul have native Wasm support
3. **Leverages existing trait system**: Uses `Add`, `Sub`, `Mul`, `Eq`, `Ord` traits from WEP-2026-01-18
4. **Incremental implementation**: Can be developed and tested step by step
5. **Maintainability**: All implementation in Wado code, not scattered across compiler modules

### Type Definitions

```wado
/// Signed 128-bit integer
pub struct i128 {
    low: i64,
    high: i64,  // sign bit is in high
}

/// Unsigned 128-bit integer
pub struct u128 {
    low: u64,
    high: u64,
}
```

The low/high split matches Wasm wide arithmetic conventions where each 128-bit value is represented as a pair of i64 values.

### Builtin Functions

Add to `core/builtin.wado`:

```wado
/// 128-bit addition: (a_lo, a_hi) + (b_lo, b_hi) → (result_lo, result_hi)
pub fn i64_add128(a_lo: i64, a_hi: i64, b_lo: i64, b_hi: i64) -> [i64, i64];

/// 128-bit subtraction: (a_lo, a_hi) - (b_lo, b_hi) → (result_lo, result_hi)
pub fn i64_sub128(a_lo: i64, a_hi: i64, b_lo: i64, b_hi: i64) -> [i64, i64];

/// Widening unsigned multiplication: a × b → (result_lo, result_hi)
pub fn i64_mul_wide_u(a: i64, b: i64) -> [i64, i64];

/// Widening signed multiplication: a × b → (result_lo, result_hi)
pub fn i64_mul_wide_s(a: i64, b: i64) -> [i64, i64];
```

### Arithmetic Operations

Implemented via operator overloading traits:

```wado
impl Add for i128 {
    type Output = i128;

    fn add(self, other: i128) -> i128 {
        let result = builtin::i64_add128(self.low, self.high, other.low, other.high);
        return i128 { low: result.0, high: result.1 };
    }
}

impl Sub for i128 {
    type Output = i128;

    fn sub(self, other: i128) -> i128 {
        let result = builtin::i64_sub128(self.low, self.high, other.low, other.high);
        return i128 { low: result.0, high: result.1 };
    }
}

impl Neg for i128 {
    type Output = i128;

    fn neg(self) -> i128 {
        // -x = ~x + 1 = 0 - x
        let result = builtin::i64_sub128(0, 0, self.low, self.high);
        return i128 { low: result.0, high: result.1 };
    }
}
```

### Multiplication

Full 128×128→128 multiplication requires combining multiple widening multiplications:

```wado
impl Mul for u128 {
    type Output = u128;

    fn mul(self, other: u128) -> u128 {
        // (a_lo + a_hi * 2^64) * (b_lo + b_hi * 2^64)
        // = a_lo * b_lo
        // + (a_lo * b_hi + a_hi * b_lo) * 2^64
        // + a_hi * b_hi * 2^128  (overflow, ignored)

        // Low × Low → full 128-bit result
        let lo_lo = builtin::i64_mul_wide_u(self.low as i64, other.low as i64);

        // Cross products → only need low 64 bits (high goes to overflow)
        let lo_hi = (self.low as i64) * (other.high as i64);  // wrapping
        let hi_lo = (self.high as i64) * (other.low as i64);  // wrapping

        // Combine: result_lo = lo_lo.0, result_hi = lo_lo.1 + lo_hi + hi_lo
        let result_hi = (lo_lo.1 as u64) + (lo_hi as u64) + (hi_lo as u64);
        return u128 { low: lo_lo.0 as u64, high: result_hi };
    }
}
```

### Comparison Operations

```wado
impl Eq for i128 {
    fn eq(&self, other: &Self) -> bool {
        return self.low == other.low && self.high == other.high;
    }
}

impl Ord for i128 {
    fn lt(&self, other: &Self) -> bool {
        // Signed comparison: compare high first (as signed), then low (as unsigned)
        if self.high != other.high {
            return self.high < other.high;
        }
        return (self.low as u64) < (other.low as u64);
    }
}

impl Eq for u128 {
    fn eq(&self, other: &Self) -> bool {
        return self.low == other.low && self.high == other.high;
    }
}

impl Ord for u128 {
    fn lt(&self, other: &Self) -> bool {
        // Unsigned comparison: compare high first, then low
        if self.high != other.high {
            return self.high < other.high;
        }
        return self.low < other.low;
    }
}
```

### Bitwise Operations

```wado
impl BitAnd for u128 {
    type Output = u128;
    fn bitand(self, other: u128) -> u128 {
        return u128 { low: self.low & other.low, high: self.high & other.high };
    }
}

impl BitOr for u128 {
    type Output = u128;
    fn bitor(self, other: u128) -> u128 {
        return u128 { low: self.low | other.low, high: self.high | other.high };
    }
}

impl BitXor for u128 {
    type Output = u128;
    fn bitxor(self, other: u128) -> u128 {
        return u128 { low: self.low ^ other.low, high: self.high ^ other.high };
    }
}

impl BitNot for u128 {
    type Output = u128;
    fn bitnot(self) -> u128 {
        return u128 { low: ~self.low, high: ~self.high };
    }
}

impl Shl for u128 {
    type Output = u128;
    fn shl(self, shift: u32) -> u128 {
        if shift == 0 {
            return self;
        }
        if shift >= 128 {
            return u128::zero();
        }
        if shift >= 64 {
            return u128 { low: 0, high: self.low << (shift - 64) };
        }
        // 0 < shift < 64
        let new_high = (self.high << shift) | (self.low >> (64 - shift));
        let new_low = self.low << shift;
        return u128 { low: new_low, high: new_high };
    }
}

impl Shr for u128 {
    type Output = u128;
    fn shr(self, shift: u32) -> u128 {
        // Logical right shift for unsigned
        if shift == 0 {
            return self;
        }
        if shift >= 128 {
            return u128::zero();
        }
        if shift >= 64 {
            return u128 { low: self.high >> (shift - 64), high: 0 };
        }
        // 0 < shift < 64
        let new_low = (self.low >> shift) | (self.high << (64 - shift));
        let new_high = self.high >> shift;
        return u128 { low: new_low, high: new_high };
    }
}
```

For i128, `Shr` performs arithmetic right shift (sign-extending).

## Implementation Plan

### Phase 1: Builtins

- [ ] Add `i64_add128`, `i64_sub128`, `i64_mul_wide_u`, `i64_mul_wide_s` to `builtin.wado`
- [ ] Implement Wasm codegen for these builtins

### Phase 2: Arithmetic Operator Traits (Prerequisite)

Implement WEP-2026-01-18 arithmetic traits:

- [ ] `Add`, `Sub`, `Mul`, `Div`, `Rem` traits in prelude
- [ ] `Neg` trait for unary minus
- [ ] Compiler support for desugaring `a + b` to `a.add(b)`

### Phase 3: Bitwise Operator Traits

- [ ] `BitAnd`, `BitOr`, `BitXor`, `BitNot` traits
- [ ] `Shl`, `Shr` traits

### Phase 4: i128/u128 Implementation

- [ ] Struct definitions in `core/prelude.wado` or `core/int128.wado`
- [ ] Constructors and conversion methods
- [ ] Arithmetic trait implementations
- [ ] Comparison trait implementations (`Eq`, `Ord`)
- [ ] Bitwise trait implementations
- [ ] Display implementation

### Phase 5: Testing

- [ ] Unit tests for all operations
- [ ] Edge case tests (overflow, underflow, division by zero)
- [ ] Comparison with reference implementations

## Consequences

### Positive

1. **Consistent design**: Uses same trait system as other types
2. **Maintainable**: Implementation in Wado, not scattered in compiler
3. **Extensible**: Pattern can be used for other wide types (u256, etc.)
4. **Validates operator overloading**: Good test case for the trait system

### Negative

1. **Depends on operator overloading**: Cannot implement until Phase 2 is complete

### Trade-offs

| Aspect                  | Struct approach | Builtin approach |
| ----------------------- | --------------- | ---------------- |
| Cast `42 as i128`       | Supported       | Supported        |
| Compiler complexity     | Low             | High             |
| Implementation location | Wado stdlib     | Compiler         |
| Incremental development | Easy            | Difficult        |
