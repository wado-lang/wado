# WEP: Normalized IR (NIR) Layer

## Context

The compiler pipeline from `lower` to `wir_build` runs entirely on `FlatPackage` with TIR-shaped function bodies:

```
... → link → monomorphize → erase → lower → optimize → wir_build → ...
                                    └─── FlatPackage (TIR bodies) ───┘
```

`lower/` is a series of `FlatPackage → FlatPackage` transformations (`wide_int`, `pattern`, `globals`, `boxing`, `closure`, `string`, `value_copy`). The output is structurally the same type as the input.

This produces three problems that compound over time:

- Optimize and `wir_build` see the union of pre-lower and post-lower TIR variants. Several passes carry match arms for variants that `lower` has, in practice, eliminated. These arms are required for exhaustiveness but never taken at runtime.
- The "lower has run" precondition is implicit. A newly written pass can rely on a pre-lower shape; the type system does not catch it.
- Variants that pre-lower passes (annotate, synthesis, monomorphize) need but post-lower passes do not, and vice versa, share one enum. Neither side can shrink without breaking the other.

A second pressure reinforces the first. Removing the AST-level `desugar` phase (see [LSP architecture](./wep-2026-04-18-lsp-architecture.md)) would push additional variants into TIR. Without a downstream type boundary, every optimize pass would grow further. A boundary at `lower` contains the blast radius.

## Decision

Introduce **NIR (Normalized IR)** — a separately-typed body IR. `lower/`'s output type changes from `FlatPackage` to `NirPackage`. `optimize/` and `wir_build/` consume `NirPackage`.

### What NIR Is

NIR is structurally derived from TIR. At the moment NIR lands, its expression, statement, type, and container shapes are identical to their TIR counterparts. They are distinct Rust types — separate enums, separate visitor traits — but they represent the same data.

The content of this Decision is the type boundary, not a shape redesign:

- TIR is what flows from `annotate` through `synthesis` / `effect_check` / `link` / `monomorphize` / `erase` into `lower`'s input.
- NIR is what flows out of `lower` through `optimize` into `wir_build`.
- A function signature naming one of these never names the other.

### What NIR Is Not

- Not a redesign. This WEP introduces no new node kinds, removes no variants, and changes no semantic behaviour. Wasm output is bit-identical before and after.
- Not a host for new explicit node kinds. NIR's direction is subtractive: variants that `lower` eliminates lose their place in NIR, and variants that only `lower`'s input needs lose their place in TIR. Adding new node kinds for lowered concepts (e.g., a distinct `Alloc` node for boxing) is a non-goal — type information and metadata on existing nodes are preferred over new variants.
- Not a CFG or SSA representation. NIR keeps TIR's tree-structured shape. Wado has no borrow check, and Wasm has structured control flow; the tree shape is appropriate.
- Not the home for sugar removal. Sugar elimination is `desugar`'s responsibility today, on AST. If `desugar` is later removed, sugar elimination moves to `lower_tir` (AST → TIR). Neither path produces sugar that flows into NIR.
- Not a replacement for FlatPackage. FlatPackage continues to be the pre-lower container; NirPackage is the post-lower container. Both exist after this WEP.

### Why "Normalized"

The name signals that NIR is the canonical form of a function body after lowering has run. "Normalized" captures the subtractive direction: only variants that survive lowering are part of NIR's enum, and TIR is free to drop variants that exist solely for post-lower passes. Both enums shrink toward their minimum useful shapes, while semantic behaviour stays unchanged.

(The Mesa shader compiler also names its IR NIR. The collision is in a different domain.)

## Implementation

### Source Files

| File             | Description                                                                                              |
| ---------------- | -------------------------------------------------------------------------------------------------------- |
| `nir.rs`         | NIR data structures: `NirExpr`, `NirStmt`, `NirPattern`, `NirPackage`. Initially direct copies of TIR's. |
| `nir_visitor.rs` | NIR visitor trait. Initially a direct copy of `tir_visitor.rs`.                                          |
| `nir_unparse.rs` | NIR → pseudo-Wado renderer for `wado dump --nir`.                                                        |

### Container

`NirPackage` mirrors `FlatPackage`: function table, type table reference, global table, exports, imports. Field shapes match initially.

### Data Sharing With TIR

NIR reuses without copying:

- `TypeTable` (post-erase): types are interned globally, not per IR. NirPackage holds a reference in the same shape FlatPackage does.
- `SymbolKey`, `FunctionId`, `GlobalId`, name interners.
- `Literal`: value representation is independent of expression shape.

NIR owns its own:

- Expression / statement / pattern enums and their inline metadata.
- Visitor trait.

This follows the convention `WirPackage` already uses: `WirTypeId` borrows TIR-level type identity, while `WirInstr` is a fresh enum.

### Lower Phase Role

`lower/` continues to perform the same semantic work. Only its output type changes:

```rust
// Before
fn lower(package: FlatPackage) -> FlatPackage

// After
fn lower(package: FlatPackage) -> NirPackage
```

Because NIR is initially structurally identical to TIR, the cross-type conversion at lower's exit is mechanical: field-for-field reconstruction. The internal sub-passes (`wide_int`, `pattern`, `globals`, `boxing`, `closure`, `string`, `value_copy`) keep their current implementations.

### Inspection

`wado dump --nir` renders `NirPackage` as pseudo-Wado, paralleling `--tir` and `--wir`.

## Migration Plan

NIR starts structurally identical to TIR. No parallel pipeline (strangler fig) is required; the change is a sequence of in-place renames.

### Phase 1: Add NIR types

- [x] Create `nir.rs`, `nir_visitor.rs`, `nir_unparse.rs` as renamed copies of their TIR counterparts.
- [x] Create `NirPackage` as a renamed copy of `FlatPackage`.
- [x] Wire `wado dump --nir`.

No pipeline change yet. E2E tests are unaffected.

### Phase 2: Lower returns NirPackage

- [x] Add a `FlatPackage → NirPackage` conversion at the exit of `lower/`.
- [x] Change `lower/`'s public signature.
- [x] Add a temporary `NirPackage → FlatPackage` adapter so downstream consumers continue to work unchanged.

### Phase 3: Migrate `optimize/`

- [x] Rename `TirExpr`/`TirStmt`/`FlatPackage` references inside `optimize/` to their NIR counterparts, pass by pass.
- [x] Each pass migration is mechanical — same logic, renamed types.

### Phase 4: Migrate `wir_build/`

- [x] Change `wir_build/build_wir_package`'s input type to `NirPackage`.
- [x] Rename references inside `wir_build/`.

### Phase 5: Remove the temporary adapter

- [x] Delete the `NirPackage → FlatPackage` adapter added in Phase 2.
- [x] Confirm E2E tests pass with the full NIR pipeline.

### Phase 6: Trim pre-lower-only variants from NIR

The type boundary makes the dead-arm cleanup mechanical. With NIR
distinct from TIR, every variant that `lower` / `synthesis` /
`monomorphize` always eliminate before NIR is constructed can leave
NIR's enum, and every consumer's exhaustiveness arm for it disappears.

- [x] Drop from `NirExprKind`: `Closure`, `Capture`, `FuncRef`,
      `TemplateString`, `WithHandler`, `Resume`, `TupleSpread`,
      `TupleZip`, `TypePackExpansion`.
- [x] Drop from `NirStmtKind`: `IfLet`, `TaskReturn`, `VariadicForOf`.
- [x] Keep `NirStmtKind::LetDestructure` — `lower::pattern` preserves
      it post-lower when the value is a multi-value core-builtin call
      and the pattern is a flat tuple of bindings, so codegen can use
      its multi-value optimisation.

- [x] Drop `TirExprKind::ClosureToCanonical` — now built only by
      the TIR → NIR translator (`Closure` / `Capture` survive in
      TIR untouched; the translator emits
      `NirExprKind::ClosureToCanonical` for remaining closures and
      fn-param-`Local` arg slots in specialized callee bodies).

### Phase 7: Lower pipeline → planner + translator

- [x] Move every TIR-mutating sub-pass into `lower::plan::*`:
      `pattern` / `globals::extract` / `boxing` / `closure` /
      `globals::build_initialize_modules` / `value_copy` / `string`.
      `lower::lower` reduces to `plan + translate`; the in-place
      pipeline is gone.
- [x] Migrate the wide-int `Match` → if-else rewrite into the
      translator (`lower::translate::wide_int`). `lower/wide_int.rs`
      deleted; shared literal builders extracted to
      `lower::wide_int_literal`.
- [x] Migrate the closure-call-site rewriters
      (`RemainingClosuresRewriter`, `SpecializerTransformer`) into the
      translator. `ClosurePlan` carries `functor_infos` and per
      specialized callee `specialized_locals` for the translator's
      per-function context.

### Phase 9: Internal cleanup of the lower phase

- [x] Phase 9.A — drop `temp_module` wrapping in planner
      sub-passes; pass internals take `&mut FlatPackage` directly.
- [x] Phase 9.B — drop vestigial body-IR fields from
      `FlatPackage` / `TirModule`; `LowerPlan` carries them
      instead.
- [x] Phase 9.D — replace `Cell`-based per-function slot on
      `Translator` with a `FunctionTranslator<'a, 'p>`
      sub-context. Hosts per-function state pattern lowering /
      future per-function passes need.
- [x] Phase 9.C.1 — relocate pattern lowering to
      `lower::translate::pattern` and move dense-int `Match` →
      `Switch` into `lower::translate::switch`.

      Pattern lowering still runs first in `lower::plan::plan`:
      it peels `Ref`/`MutRef` from scrutinees, and `boxing`
      rewrites `&Variant` into `Box<Variant>` later, hiding the
      peel.
- [ ] Phase 9.C.2 — rewrite `IfLet` to a two-arm `Match` in
      `lower::translate::pattern::lower_stmt`. Attempted in this
      branch (the bespoke `lower_if_pattern_option` /
      `lower_if_pattern_struct` /
      `lower_if_let_with_literal_sub_patterns` /
      `pattern_to_condition_and_bindings` /
      `build_pattern_check` / `peel_ref_scrutinee` helpers were
      removed in favour of a 2-arm Match that flows through
      `wir_build::pattern_match`), but reverted: the optimizer's
      variant SROA pass scalarizes a freshly-constructed variant
      across an `If VariantTest + VariantPayload` consumer and
      doesn't recognize Match arm-binding extraction. The hot
      `for-of` byte loop desugars to
      `if let Some(b) = iter.next() { ... } else break`, where
      `iter.next()` returns a fresh `struct.new Option<u8>` per
      iteration. The 2-arm Match shape left that allocation in
      place per iteration; fts regressed 4-8× on -O1/-O2/-O3.

      Two paths land 9.C.2 cleanly:

      - Add a NIR-level pass that rewrites a 2-arm
        `Match { Variant(b) => then, _ => else }` into the
        explicit `Let __scrut + If VariantTest + Let bindings =
        VariantPayload + then ` shape *before* SROA runs.
        Pattern lowering stays simple; the optimizer recovers
        the SROA-friendly shape.

      - Or teach `optimize::sroa` to scalarize variant aggregates
        through Match arm bindings directly, recognizing the
        same `(scrutinee fresh-constructed) × (matched arm
        extracts payload)` pattern that `VariantTest` /
        `VariantPayload` consumers expose today.

      Three supporting fixes from the attempt are kept in place
      (they're improvements regardless and no longer have a
      specific 9.C.2 consumer; the synthesis-emitted `if let`
      paths and any future Match-arm-binding path will benefit
      when 9.C.2 lands again):

      - `LocalCollector::visit_pattern` in `lower::plan::closure`
        registers pattern-binding locals so closure-body
        Match-arm bindings see their slots in the generated
        `__call` method.

      - `wir_build::pattern_match::emit_pattern_binding_set`
        unifies Box / `RefAsNonNull` coercion across the variant
        payload binding and tuple destructure binding emitters,
        replacing two near-duplicate code paths.

      - `block_result_type` moves from `Resolver` to a shared
        `crate::tir::block_result_type` free function; the
        resolver and pattern lowering both delegate.
- [ ] Phase 9.C.3 — migrate the synthesis producers of
      `TirExprKind::{Switch, VariantTag, VariantTest,
      VariantPayload}` and `TirStmtKind::IfLet` to plain `Match`
      / explicit `If` chains. Construction sites today:
      `synthesis/traits.rs` (eq/ord/hash bodies),
      `synthesis/serde_synth.rs`, `synthesis/template.rs`,
      `synthesis/effect_dispatch.rs`, `synthesis/cm_binding/*`.
      After 9.C.2 lands the translator can lower those forms uniformly.

      Migration sketch (every variant has the same shape):

      - `VariantTest(value, case)` → `match value { Case(_) =>
        true, _ => false }`. Pattern `Variant { bindings: [_; n] }`
        where `n` matches the case's payload arity (`Wildcard`s
        for each payload field). `wir_build::pattern_match`
        compiles to the same `ref.test` + branch sequence the
        explicit `VariantTest` emitted.

      - `VariantPayload(value, case, payload_type)` → bind the
        payload directly: `match value { Case(p) => p, _ =>
        unreachable!() }`. Synthesis allocates a fresh `TirLocal`
        for `p` per call site; the surrounding context already
        threads `next_local` / `locals` (every
        `synthesis/cm_binding/lower.rs` helper takes `&mut u32`
        and `&mut Vec<TirLocal>`). The `_` arm's body is the
        existing `core:internal/unreachable` call.

      - `VariantTag(value)` → `match value { Case_0 => 0, Case_1
        => 1, ..., Case_N => N }`. The caller already knows the
        case list (every `variant_tag` call site sits inside a
        loop over `cases`); pass the case list to the helper so
        it can build an arm per case.

      - `Switch { scrutinee, min_value, arms, default }` →
        emit as `Match`; the translator's
        `lower::translate::switch` rebuilds a TIR `Switch` for
        dense-int matches. Non-dense matches stay as `Match` and
        flow through to NIR `Match`.

      - `IfLet { scrutinee, pattern, then, else }` → `match
        scrutinee { pattern => then, _ => else.unwrap_or(unit) }`.
        Pattern lowering already does this exact rewrite for
        user-written `if let`; the synthesis-emitted form lands on
        the same path.

      Two helpers worth sharing across the synthesis crates
      before the migration:

      - `synthesis::common::match_variant_test(value, variant_ty,
        case_index, case_name, payload_arity)` — returns a TIR
        `Match` of `BOOL` type. Replaces every
        `cm_binding::types::variant_test` and
        `synthesis::traits::*::variant_test` call site.

      - `synthesis::common::match_variant_payload(value,
        variant_ty, case_index, case_name, payload_type,
        next_local, locals)` — allocates a fresh payload local,
        returns a `(let_stmt, local_ref_expr)` pair so the caller
        can splice the let into the surrounding block and use the
        local in subsequent expressions.

      `effect_dispatch.rs` has the most call sites; the
      `match_variant_test` helper covers the common case,
      with `match_variant_payload` for the rest. The IfLet
      callers (`serde_synth.rs::if_let_ok` /
      `if_let_some`) become `match_variant_test_with_binding`
      wrappers — combining test + payload-binding into a single
      Match for the common "test then extract" pattern.

      Size: ~30 producer call sites across synthesis. Each is
      mechanical once the helpers land; tests at every commit.

- [ ] Phase 9.C.4 — drop `TirExprKind::{Switch, VariantTag,
      VariantTest, VariantPayload}` and `TirStmtKind::IfLet`
      (`LetDestructure` stays because the resolver still emits it
      and NIR preserves the multi-value optimisation). Clean up
      consumer arms in `tir_visitor.rs`, `unparse.rs`,
      `effect_check.rs`, `synthesis/*` walkers, `monomorphize/*`,
      and the remaining `lower::*` walkers. After 9.C.3 the
      enum has no producers, so the deletion is a mechanical
      "remove the variant + all `match` arms covering it" sweep.

      The `lower::translate::pattern::lower_stmt` path that
      converts user-written `IfLet` to `Match` becomes an
      AST-level desugaring instead — `lower_tir` (or the
      resolver) emits `Match` directly, and pattern lowering
      drops its IfLet arm. The `Match` arm preprocessing
      (`or` expansion, ref deref, refutable sub-pattern →
      guard) stays where it is.

Subsequent work (removing the AST-level `desugar` phase) is out of
scope for this WEP. Each lands as its own follow-up.

## Consequences

### Benefits

- Type boundary at `lower`. The "lower has run" precondition is enforced statically.
- Risk concentrates on `lower`. Optimize and `wir_build` migrations are mechanical renames; the semantically interesting work stays in the smallest of the three phases.
- Enables variant trimming on both sides. With two distinct enums, variants only meaningful pre-lower can leave NIR, and variants only meaningful post-lower can leave TIR. Each trim is a small PR enforced by the type system.
- Enables removal of the AST-level `desugar` phase. Adding variants to TIR (the consequence of moving sugar elimination into `lower_tir`) does not propagate into optimize.

### Trade-offs

- Code duplication on landing. NIR's expression / statement / visitor / unparse files start as copies of TIR's. The duplication is intentional and is paid down in subsequent WEPs as the two diverge. Copying is mechanical and reviewable in one sitting.
- A short window during the transition where both `FlatPackage` and `NirPackage` flow through downstream code. The Phase 2 adapter absorbs this; Phase 5 removes it.
- One more `wado dump` mode to maintain.
