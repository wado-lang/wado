# WEP: Normalized IR (NIR) Layer

## Context

The compiler pipeline from `lower` to `wir_build` runs entirely on `FlatPackage` with TIR-shaped function bodies:

```
... → link → monomorphize → erase → lower → optimize → wir_build → ...
                                    └─── FlatPackage (TIR bodies) ───┘
```

`lower/` is a series of `FlatPackage → FlatPackage` transformations (`wide_int`, `pattern`, `globals`, `boxing`, `closure`, `string`, `value_copy`). The output is structurally the same type as the input.

This produces three problems that compound over time:

- Optimize and `wir_build` see the union of pre-lower and post-lower TIR variants. Several passes carry match arms for variants that `lower` has, in practice, eliminated. These arms are required for exhaustiveness but never taken at runtime.
- The "lower has run" precondition is implicit. A newly written pass can rely on a pre-lower shape; the type system does not catch it.
- Variants that pre-lower passes (annotate, synthesis, monomorphize) need but post-lower passes do not, and vice versa, share one enum. Neither side can shrink without breaking the other.

A second pressure reinforces the first. Removing the AST-level `desugar` phase (see [LSP architecture](./wep-2026-04-18-lsp-architecture.md)) would push additional variants into TIR. Without a downstream type boundary, every optimize pass would grow further. A boundary at `lower` contains the blast radius.

## Decision

Introduce **NIR (Normalized IR)** — a separately-typed body IR. `lower/`'s output type changes from `FlatPackage` to `NirPackage`. `optimize/` and `wir_build/` consume `NirPackage`.

### What NIR Is

NIR is structurally derived from TIR. At the moment NIR lands, its expression, statement, type, and container shapes are identical to their TIR counterparts. They are distinct Rust types — separate enums, separate visitor traits — but they represent the same data.

The content of this Decision is the type boundary, not a shape redesign:

- TIR is what flows from `annotate` through `synthesis` / `effect_check` / `link` / `monomorphize` / `erase` into `lower`'s input.
- NIR is what flows out of `lower` through `optimize` into `wir_build`.
- A function signature naming one of these never names the other.

### What NIR Is Not

- Not a redesign. This WEP introduces no new node kinds, removes no variants, and changes no semantic behaviour. Wasm output is bit-identical before and after.
- Not a host for new explicit node kinds. NIR's direction is subtractive: variants that `lower` eliminates lose their place in NIR, and variants that only `lower`'s input needs lose their place in TIR. Adding new node kinds for lowered concepts (e.g., a distinct `Alloc` node for boxing) is a non-goal — type information and metadata on existing nodes are preferred over new variants.
- Not a CFG or SSA representation. NIR keeps TIR's tree-structured shape. Wado has no borrow check, and Wasm has structured control flow; the tree shape is appropriate.
- Not the home for sugar removal. Sugar elimination is `desugar`'s responsibility today, on AST. If `desugar` is later removed, sugar elimination moves to `lower_tir` (AST → TIR). Neither path produces sugar that flows into NIR.
- Not a replacement for FlatPackage. FlatPackage continues to be the pre-lower container; NirPackage is the post-lower container. Both exist after this WEP.

### Why "Normalized"

The name signals that NIR is the canonical form of a function body after lowering has run. "Normalized" captures the subtractive direction: only variants that survive lowering are part of NIR's enum, and TIR is free to drop variants that exist solely for post-lower passes. Both enums shrink toward their minimum useful shapes, while semantic behaviour stays unchanged.

(The Mesa shader compiler also names its IR NIR. The collision is in a different domain.)

## Implementation

### Source Files

| File             | Description                                                                                              |
| ---------------- | -------------------------------------------------------------------------------------------------------- |
| `nir.rs`         | NIR data structures: `NirExpr`, `NirStmt`, `NirPattern`, `NirPackage`. Initially direct copies of TIR's. |
| `nir_visitor.rs` | NIR visitor trait. Initially a direct copy of `tir_visitor.rs`.                                          |
| `nir_unparse.rs` | NIR → pseudo-Wado renderer for `wado dump --nir`.                                                        |

### Container

`NirPackage` mirrors `FlatPackage`: function table, type table reference, global table, exports, imports. Field shapes match initially.

### Data Sharing With TIR

NIR reuses without copying:

- `TypeTable` (post-erase): types are interned globally, not per IR. NirPackage holds a reference in the same shape FlatPackage does.
- `SymbolKey`, `FunctionId`, `GlobalId`, name interners.
- `Literal`: value representation is independent of expression shape.

NIR owns its own:

- Expression / statement / pattern enums and their inline metadata.
- Visitor trait.

This follows the convention `WirPackage` already uses: `WirTypeId` borrows TIR-level type identity, while `WirInstr` is a fresh enum.

### Lower Phase Role

`lower/` continues to perform the same semantic work. Only its output type changes:

```rust
// Before
fn lower(package: FlatPackage) -> FlatPackage

// After
fn lower(package: FlatPackage) -> NirPackage
```

Because NIR is initially structurally identical to TIR, the cross-type conversion at lower's exit is mechanical: field-for-field reconstruction. The internal sub-passes (`wide_int`, `pattern`, `globals`, `boxing`, `closure`, `string`, `value_copy`) keep their current implementations.

### Inspection

`wado dump --nir` renders `NirPackage` as pseudo-Wado, paralleling `--tir` and `--wir`.

## Migration Plan

NIR starts structurally identical to TIR; the migration is a sequence
of in-place renames plus the lower-phase restructuring of Phase 10.

### Phases 1-5: NIR types + pipeline migration — done

- [x] Phase 1 — `nir.rs` / `nir_visitor.rs` / `nir_unparse.rs` and
      `NirPackage` created as renamed copies of their TIR
      counterparts; `wado dump --nir` wired.
- [x] Phase 2 — `lower/` returns `NirPackage`, behind a temporary
      `NirPackage → FlatPackage` adapter for downstream consumers.
- [x] Phase 3 — `optimize/` migrated to NIR types, pass by pass.
- [x] Phase 4 — `wir_build/` consumes `NirPackage`.
- [x] Phase 5 — temporary adapter removed; full NIR pipeline green.

### Phase 6: Trim pre-lower-only variants from NIR — done

- [x] Dropped from `NirExprKind`: `Closure`, `Capture`, `FuncRef`,
      `TemplateString`, `WithHandler`, `Resume`, `TupleSpread`,
      `TupleZip`, `TypePackExpansion`; from `NirStmtKind`: `IfLet`,
      `TaskReturn`, `VariadicForOf`. `NirStmtKind::LetDestructure`
      kept for the multi-value core-builtin optimisation.
      `TirExprKind::ClosureToCanonical` dropped — the translator
      emits `NirExprKind::ClosureToCanonical` directly.

### Phases 7 + 9: Lower pipeline → planner + translator — done

- [x] Every TIR-mutating sub-pass moved into `lower::plan::*`
      (`pattern` / `globals` / `boxing` / `closure` / `value_copy`
      / `string`); `lower::lower` reduced to `plan + translate`.
- [x] wide-int `Match`→if-else and the closure call-site rewriters
      folded into the translator; `lower/wide_int.rs` deleted.
- [x] Phase 9 — `temp_module` wrapping dropped; vestigial body-IR
      fields removed from `FlatPackage`/`TirModule` (carried by
      `LowerPlan`); `Cell`-based translator slot replaced with a
      `FunctionTranslator<'a,'p>` sub-context; pattern lowering
      relocated to `lower::translate::pattern`, dense-int
      `Match`→`Switch` to `lower::translate::switch`.

### Phase 10: Match Canonical Direction

`Match` is NIR's canonical pattern-matching form; `Switch` is the
codegen-friendly dense form the optimiser materialises. `Match`
preserves structural pattern-matching info (scrutinee identity, arm
order, payload bindings, or-patterns, guards) that optimisations
depend on; lowering to `If + VariantTest + Let` scatters it across
statements and discards or-patterns / exhaustiveness / binding
topology. The `Match → Switch` slot mirrors `select_lowering` — a
late codegen-oriented lowering done by the optimiser, not baked into
the IR by lowering.

Final NIR shape after this work:

- `NirExprKind::Match` — canonical pattern-matching form
- `NirExprKind::Switch` — dense-int / dense-enum form, only emitted
  by `optimize::match_to_switch`
- `NirExprKind::{VariantTag, VariantTest, VariantPayload}` — to be
  removed (Step 5)

#### Step 1: Match → Switch is an optimiser pass — done

- [x] `optimize::match_to_switch` walks NIR and materialises
      `Switch` for dense-int / dense-enum scrutinees; the translator
      only ever emits canonical `Match`.

#### Step 2: Pattern lowering into the translator

- [x] Step 2a — done. `lower::translate::pattern::lower` lowers
      `IfLet` to a two-arm TIR `Match` (binding the scrutinee to a
      fresh `__iflet_N` local first, so `labeled_block_fusion` still
      sees the `(Let, Match)` pair); `closure::LocalCollector`
      extended to visit pattern bindings so arm-bound locals reserve
      the correct payload type; the `mut`-payload-binding lift
      extracted into a stand-alone `lift_mut::lift_mut_match_bindings`
      plan sub-pass, which also decouples `value_copy` from pattern
      lowering. Full 6292-fixture e2e suite green at O0/O1/O2/O3/Os.

- [x] Step 2b prerequisite — pattern lowering relocated after
      `boxing`, no longer dependent on Step 6. The earlier analysis
      held that pattern lowering had to run before `boxing` because
      its scrutinee ref-deref only peeled `ResolvedType::Ref` /
      `MutRef`, so once `boxing` turned `&Variant` into a `Box<T>`
      struct the peel stopped firing. The fix is to make pattern
      lowering box-aware rather than to make `boxing` analysis-only:
  - `peel_refs_and_box` peels `Box<T>` struct wrappers (via a
    `.value` field access) alongside `Ref` / `MutRef`.
  - `coerce_value_to_binding` materialises a `Box<T>` struct
    literal for an ergonomic reference binding, the shape `boxing`
    would have produced.
  - Binding `Let` statements take their type from the binding
    local, authoritative after `boxing`'s address-taken promotion.
    Both helpers degrade to plain `Ref` peeling when the
    box-payload registry is empty, so they are order-independent.
    Full 6347-fixture e2e suite green at O0/O1/O2/O3/Os. `boxing`
    was also split into `prepare_types` (type-table preparation)
    and `lower_bodies` (TIR body rewriting) as Step 6 groundwork.

- [x] Step 2b — done. Pattern lowering is no longer a `lower::plan`
      sub-pass. `translate::pattern` exposes a `Lowering` context;
      `translate` runs `Lowering::lower_function` over every function
      before the fold begins, so `IfLet` / `LetDestructure` /
      or-pattern rewriting lives entirely inside `translate`.
      `string` literal collection also moved into `translate`,
      _after_ pattern lowering: pattern lowering rewrites a
      string-literal pattern into a `String::eq` guard against a
      synthesised string-literal expression, and the data section
      must register those literals — a `plan`-phase `string::plan`
      ran too early and left them aliasing data segment 0.
      `lift_mut` already handles `IfLet` and `Match` patterns
      directly, and `value_copy` does not depend on pattern lowering
      having run. The WEP's earlier claim that Step 2b was blocked
      on Step 6 was incorrect on the `boxing` count; the real
      dependency was `string::plan`, resolved by moving it into
      `translate`. Full 6352-fixture e2e suite green at
      O0/O1/O2/O3/Os; `mise run test-wado` 2820 tests passing.

#### Step 3: Synthesis migration

- [x] Migrated to canonical TIR `Match` (arms use
      `TirPattern::Variant { bindings: [Binding] }`, payloads bound
      to generator-allocated locals): `synthesis/traits.rs`
      (`Inspect` / `InspectAlt` / `Eq`), `serde_synth.rs`,
      `effect_dispatch.rs`, and all of `cm_binding`
      (`lower.rs`, `export_adapter.rs`, `task_return.rs`). Shared
      helpers `synthesis::common::match_variant_test` /
      `match_variant_payload` cover the common shapes.
- [ ] Remaining `variant_test(...)` / `variant_payload(...)` /
      `variant_tag(...)` references in cm_binding (`export_adapter.rs`,
      `lower.rs`, `task_return.rs`) are all **expression-value**
      uses, not control flow: the CM discriminant byte at offset 0
      (`variant_test`/`variant_tag` cast to integer) and a few
      statically-known `variant_payload` extractions in lift/lower
      helpers. They stay until Step 4 introduces a Match-equivalent
      expression form:
  - `VariantTest(v, c)` → `match v { Case(_) => true, _ => false }`
  - `VariantPayload(v, c, t)` → `match v { Case(p) => p, _ => unreachable!() }`
  - `VariantTag(v)` → `match v { Case_0 => 0, …, Case_N => N }`

#### Step 4: Drop TIR variants

- [ ] Drop `TirStmtKind::IfLet` and
      `TirExprKind::{Switch, VariantTag, VariantTest, VariantPayload}`.
      Sweep consumer arms in `tir_visitor.rs`, `unparse.rs`,
      `effect_check.rs`, the remaining `synthesis/*` /
      `monomorphize/*` walkers, and `lower::translate/*`.
      `LetDestructure` stays because the resolver still emits it
      and NIR preserves the multi-value optimisation.

#### Step 5: Drop NIR variants

- [ ] Drop `NirExprKind::{VariantTag, VariantTest, VariantPayload}`.
      `NirPattern::Variant { bindings }` is the sole way to extract
      a variant payload after this lands; `wir_build::pattern_match`
      is the sole compiler of `Match` to Wasm `ref.test` + branch.

#### Step 6 (stretch): Plan sub-passes become analysis-only

Goal: `boxing` / `closure` / `value_copy` / `globals` stop mutating
`FlatPackage` and instead return analysis structs that
`lower::translate` consumes during the fold, so `lower::lower(flat)`
is a pure TIR → NIR fold with no TIR-mutating pre-pass. Making
`boxing` analysis-only is what unblocks Step 2b.

Findings from reading the four passes (2026-05-20):

- [ ] `boxing` analysis-only (~1300 LoC). No longer the Step 2b
      blocker — Step 2b's prerequisite is done independently. `boxing`
      is already split into `prepare_types` (mints `Box<T>` struct
      types, redefines `Ref`/`MutRef` TypeIds — type-table only) and
      `lower_bodies` (the TIR body rewrites). `prepare_types` returns
      a `BoxPlan` carrying the type-level facts. Remaining work: the
      body rewrites in `lower_bodies` (7 expr rules: `&local`→`local`,
      boxed-`local` read→`.value`, `*box`→`.value`, deref-assign field
      expansion, …) move into the translator's `convert_expr`, driven
      by the `BoxPlan`. The type-table redefinition in `prepare_types`
      stays as a pre-pass: it is the only mechanism that lets
      composite types (`Array<&i32>`, …) follow the `Ref → Box`
      rewrite without a combinatorial set of parallel TypeIds.
- [ ] `closure` analysis-only (~1900 LoC). Additive parts (functor
      structs, `__call` methods) may stay; the body rewrites
      (`Closure`→functor literal, `Capture`→`FieldAccess`,
      call-site rewriting) move into the fold.
- [ ] `globals` analysis-only (~850 LoC). `extract` moves global
      initializers into `__initialize_module` functions; the
      synthesized init functions are additive, the initializer
      extraction folds in.
- [ ] `value_copy` analysis-only — `insert` (~340 LoC) inserts
      `$value_copy$T` marker calls; `synthesize` (~800 LoC) adds the
      helper functions (additive, may stay). `value_copy` no longer
      blocks Step 2b — the `lift_mut` decoupling is done.

Sequencing caveat: the passes are interdependent — `boxing` runs
first and `closure` / `value_copy` consume boxed TIR, so a single
pass cannot be made analysis-only in isolation without breaking
ordering. The `boxing` half of Step 6 and Step 2b should land
together, and the cluster is best migrated as one focused effort
(no green intermediate checkpoint between mutating and folded form).

Subsequent work (removing the AST-level `desugar` phase) is out of
scope for this WEP. Each lands as its own follow-up.

## Consequences

### Benefits

- Type boundary at `lower`. The "lower has run" precondition is enforced statically.
- Risk concentrates on `lower`. Optimize and `wir_build` migrations are mechanical renames; the semantically interesting work stays in the smallest of the three phases.
- Enables variant trimming on both sides. With two distinct enums, variants only meaningful pre-lower can leave NIR, and variants only meaningful post-lower can leave TIR. Each trim is a small PR enforced by the type system.
- Enables removal of the AST-level `desugar` phase. Adding variants to TIR (the consequence of moving sugar elimination into `lower_tir`) does not propagate into optimize.

### Trade-offs

- Code duplication on landing. NIR's expression / statement / visitor / unparse files start as copies of TIR's. The duplication is intentional and is paid down in subsequent WEPs as the two diverge. Copying is mechanical and reviewable in one sitting.
- A short window during the transition where both `FlatPackage` and `NirPackage` flow through downstream code. The Phase 2 adapter absorbs this; Phase 5 removes it.
- One more `wado dump` mode to maintain.
