# WEP: Normalized IR (NIR) Layer

## Context

The compiler pipeline from `lower` to `wir_build` runs entirely on `FlatPackage` with TIR-shaped function bodies:

```
... → link → monomorphize → erase → lower → optimize → wir_build → ...
                                    └─── FlatPackage (TIR bodies) ───┘
```

`lower/` is a series of `FlatPackage → FlatPackage` transformations (`wide_int`, `pattern`, `globals`, `boxing`, `closure`, `string`, `value_copy`). The output is structurally the same type as the input.

This produces three problems that compound over time:

- Optimize and `wir_build` see the union of pre-lower and post-lower TIR variants. Several passes carry match arms for variants that `lower` has, in practice, eliminated. These arms are required for exhaustiveness but never taken at runtime.
- The "lower has run" precondition is implicit. A newly written pass can rely on a pre-lower shape; the type system does not catch it.
- Variants that pre-lower passes (annotate, synthesis, monomorphize) need but post-lower passes do not, and vice versa, share one enum. Neither side can shrink without breaking the other.

A second pressure reinforces the first. Removing the AST-level `desugar` phase (see [LSP architecture](./wep-2026-04-18-lsp-architecture.md)) would push additional variants into TIR. Without a downstream type boundary, every optimize pass would grow further. A boundary at `lower` contains the blast radius.

## Decision

Introduce **NIR (Normalized IR)** — a separately-typed body IR. `lower/`'s output type changes from `FlatPackage` to `NirPackage`. `optimize/` and `wir_build/` consume `NirPackage`.

### What NIR Is

NIR is structurally derived from TIR. At the moment NIR lands, its expression, statement, type, and container shapes are identical to their TIR counterparts. They are distinct Rust types — separate enums, separate visitor traits — but they represent the same data.

The content of this Decision is the type boundary, not a shape redesign:

- TIR is what flows from `annotate` through `synthesis` / `effect_check` / `link` / `monomorphize` / `erase` into `lower`'s input.
- NIR is what flows out of `lower` through `optimize` into `wir_build`.
- A function signature naming one of these never names the other.

### What NIR Is Not

- Not a redesign. This WEP introduces no new node kinds, removes no variants, and changes no semantic behaviour. Wasm output is bit-identical before and after.
- Not a host for new explicit node kinds. NIR's direction is subtractive: variants that `lower` eliminates lose their place in NIR, and variants that only `lower`'s input needs lose their place in TIR. Adding new node kinds for lowered concepts (e.g., a distinct `Alloc` node for boxing) is a non-goal — type information and metadata on existing nodes are preferred over new variants.
- Not a CFG or SSA representation. NIR keeps TIR's tree-structured shape. Wado has no borrow check, and Wasm has structured control flow; the tree shape is appropriate.
- Not the home for sugar removal. Sugar elimination is `desugar`'s responsibility today, on AST. If `desugar` is later removed, sugar elimination moves to `lower_tir` (AST → TIR). Neither path produces sugar that flows into NIR.
- Not a replacement for FlatPackage. FlatPackage continues to be the pre-lower container; NirPackage is the post-lower container. Both exist after this WEP.

### Why "Normalized"

The name signals that NIR is the canonical form of a function body after lowering has run. "Normalized" captures the subtractive direction: only variants that survive lowering are part of NIR's enum, and TIR is free to drop variants that exist solely for post-lower passes. Both enums shrink toward their minimum useful shapes, while semantic behaviour stays unchanged.

(The Mesa shader compiler also names its IR NIR. The collision is in a different domain.)

## Implementation

### Source Files

| File             | Description                                                                                              |
| ---------------- | -------------------------------------------------------------------------------------------------------- |
| `nir.rs`         | NIR data structures: `NirExpr`, `NirStmt`, `NirPattern`, `NirPackage`. Initially direct copies of TIR's. |
| `nir_visitor.rs` | NIR visitor trait. Initially a direct copy of `tir_visitor.rs`.                                          |
| `nir_unparse.rs` | NIR → pseudo-Wado renderer for `wado dump --nir`.                                                        |

### Container

`NirPackage` mirrors `FlatPackage`: function table, type table reference, global table, exports, imports. Field shapes match initially.

### Data Sharing With TIR

NIR reuses without copying:

- `TypeTable` (post-erase): types are interned globally, not per IR. NirPackage holds a reference in the same shape FlatPackage does.
- `SymbolKey`, `FunctionId`, `GlobalId`, name interners.
- `Literal`: value representation is independent of expression shape.

NIR owns its own:

- Expression / statement / pattern enums and their inline metadata.
- Visitor trait.

This follows the convention `WirPackage` already uses: `WirTypeId` borrows TIR-level type identity, while `WirInstr` is a fresh enum.

### Lower Phase Role

`lower/` continues to perform the same semantic work. Only its output type changes:

```rust
// Before
fn lower(package: FlatPackage) -> FlatPackage

// After
fn lower(package: FlatPackage) -> NirPackage
```

Because NIR is initially structurally identical to TIR, the cross-type conversion at lower's exit is mechanical: field-for-field reconstruction. The internal sub-passes (`wide_int`, `pattern`, `globals`, `boxing`, `closure`, `string`, `value_copy`) keep their current implementations.

### Inspection

`wado dump --nir` renders `NirPackage` as pseudo-Wado, paralleling `--tir` and `--wir`.

## Migration Plan

NIR starts structurally identical to TIR. No parallel pipeline (strangler fig) is required; the change is a sequence of in-place renames.

### Phase 1: Add NIR types

- [x] Create `nir.rs`, `nir_visitor.rs`, `nir_unparse.rs` as renamed copies of their TIR counterparts.
- [x] Create `NirPackage` as a renamed copy of `FlatPackage`.
- [x] Wire `wado dump --nir`.

No pipeline change yet. E2E tests are unaffected.

### Phase 2: Lower returns NirPackage

- [x] Add a `FlatPackage → NirPackage` conversion at the exit of `lower/`.
- [x] Change `lower/`'s public signature.
- [x] Add a temporary `NirPackage → FlatPackage` adapter so downstream consumers continue to work unchanged.

### Phase 3: Migrate `optimize/`

- [x] Rename `TirExpr`/`TirStmt`/`FlatPackage` references inside `optimize/` to their NIR counterparts, pass by pass.
- [x] Each pass migration is mechanical — same logic, renamed types.

### Phase 4: Migrate `wir_build/`

- [x] Change `wir_build/build_wir_package`'s input type to `NirPackage`.
- [x] Rename references inside `wir_build/`.

### Phase 5: Remove the temporary adapter

- [x] Delete the `NirPackage → FlatPackage` adapter added in Phase 2.
- [x] Confirm E2E tests pass with the full NIR pipeline.

### Phase 6: Trim pre-lower-only variants from NIR

The type boundary makes the dead-arm cleanup mechanical. With NIR
distinct from TIR, every variant that `lower` / `synthesis` /
`monomorphize` always eliminate before NIR is constructed can leave
NIR's enum, and every consumer's exhaustiveness arm for it disappears.

- [x] Drop from `NirExprKind`: `Closure`, `Capture`, `FuncRef`,
      `TemplateString`, `WithHandler`, `Resume`, `TupleSpread`,
      `TupleZip`, `TypePackExpansion`.
- [x] Drop from `NirStmtKind`: `IfLet`, `TaskReturn`, `VariadicForOf`.
- [x] Keep `NirStmtKind::LetDestructure` — `lower::pattern` preserves
      it post-lower when the value is a multi-value core-builtin call
      and the pattern is a flat tuple of bindings, so codegen can use
      its multi-value optimisation.

- [x] Drop `TirExprKind::ClosureToCanonical` — now built only by
      the TIR → NIR translator (`Closure` / `Capture` survive in
      TIR untouched; the translator emits
      `NirExprKind::ClosureToCanonical` for remaining closures and
      fn-param-`Local` arg slots in specialized callee bodies).

### Phase 7: Lower pipeline → planner + translator

- [x] Move every TIR-mutating sub-pass into `lower::plan::*`:
      `pattern` / `globals::extract` / `boxing` / `closure` /
      `globals::build_initialize_modules` / `value_copy` / `string`.
      `lower::lower` reduces to `plan + translate`; the in-place
      pipeline is gone.
- [x] Migrate the wide-int `Match` → if-else rewrite into the
      translator (`lower::translate::wide_int`). `lower/wide_int.rs`
      deleted; shared literal builders extracted to
      `lower::wide_int_literal`.
- [x] Migrate the closure-call-site rewriters
      (`RemainingClosuresRewriter`, `SpecializerTransformer`) into the
      translator. `ClosurePlan` carries `functor_infos` and per
      specialized callee `specialized_locals` for the translator's
      per-function context.

### Phase 9: Internal cleanup of the lower phase

- [x] Phase 9.A — drop `temp_module` wrapping in planner
      sub-passes; pass internals take `&mut FlatPackage` directly.
- [x] Phase 9.B — drop vestigial body-IR fields from
      `FlatPackage` / `TirModule`; `LowerPlan` carries them
      instead.
- [x] Phase 9.D — replace `Cell`-based per-function slot on
      `Translator` with a `FunctionTranslator<'a, 'p>`

- [x] Phase 9.C.1 — relocate pattern lowering to
      `lower::translate::pattern` and move dense-int `Match` →

      Pattern lowering still runs first in `lower::plan::plan`:

### Phase 10: Match Canonical Direction (2026-05-19 update)

After 9.C.1 landed, the original 9.C.2 / 9.C.3 / 9.C.4 plan was
reconsidered. The plan kept `If + VariantTest + VariantPayload + Let`
as NIR's pattern-matching shape so that the existing optimiser passes
(notably `labeled_block_fusion` and the variant-aware helpers in
`sroa` / `condition_implication`) would not need rework. A first
attempt at 9.C.2 confirmed the cost of that constraint: rewriting
`IfLet` to a two-arm `Match` and letting `wir_build::pattern_match`
emit the variant ops at the NIR boundary missed that the optimiser
keys on the old shape, and regressed `benchmark/fts` 4–8× on
-O1/-O2/-O3 because variant SROA does not recognise Match
arm-binding extraction.

The replacement direction makes `Match` NIR's canonical pattern-
matching form and treats `Switch` as the codegen-friendly optimised
form the optimiser materialises. Rationale:

- `Match` preserves structural pattern-matching information
  (scrutinee identity, arm order, payload bindings, or-patterns,
  guards) that optimisations depend on. Lowering to
  `If + VariantTest + Let` scatters this info across multiple
  statements and discards or-patterns, exhaustiveness, and binding
  topology.
- Future optimisations — variant-flow analysis, match merging,
  exhaustiveness-driven dead-arm elimination, or-pattern compression,
  smarter `br_table`/`br_if` codegen choice — are direct on `Match`
  and fundamentally require reconstruction on `If + VariantTest`.
- NIR is the canonical Wado IR (per the Decision section above); WIR
  is the Wasm-shaped IR. Match-canonical NIR keeps the two layers
  distinct.
- The `Match` → `Switch` optimisation slot mirrors `select_lowering`'s
  existing role: a codegen-friendly late lowering from a high-level
  shape into a Wasm-shaped one, materialised by the optimiser rather
  than baked into the IR by lowering.

Final NIR shape after this work:

- `NirExprKind::Match` — canonical pattern-matching form
- `NirExprKind::Switch` — optimised dense-int / dense-enum form,
  only emitted by `optimize::match_to_switch`
- `NirExprKind::{VariantTag, VariantTest, VariantPayload}` — removed
- `NirStmtKind::IfLet` — already gone (Phase 6)
- `NirStmtKind::LetDestructure` — kept for the multi-value builtin
  optimisation

#### Step 1: Match → Switch becomes an optimiser pass

- [x] Move `lower::translate::switch::{analyze, build}` out of the
      translator into a new `optimize::match_to_switch` pass that
      walks NIR. The translator emits canonical `NirExprKind::Match`
      for every pattern; the optimiser materialises
      `NirExprKind::Switch` for dense-int / dense-enum scrutinees
      as the first step in each fixed-point iteration (and once at
      -O0 after DCE so wir_build sees `Switch` even when the
      optimisation loop is skipped).

#### Step 2 + Step 7: Pattern lowering into translator + optimiser adaption

Originally framed as an atomic PR; in practice the work split into
two refactors driven by the boxing pass's TIR-mutating contract.

- [x] Step 2a — rewrite `lower::translate::pattern::lower`'s
      `IfLet` handler to emit a TIR `Match` (two-arm: the user's
      pattern → then-block, `Wildcard` → else-block / Unit) and let
      the existing `lower_expr` Match preprocessing (or-pattern
      expansion, refutable sub-pattern extraction, ref-deref,
      top-level literal / `ConstantValue` lowering) run on the
      synthesised arms. Match's `type_id` is read off
      `tir::block_result_type`, so nested `If` / `IfLet`
      last-statements contribute their inferred result type instead
      of falling back to Unit.
- [x] Step 2a follow-up — extend `closure::LocalCollector` to visit
      pattern bindings as well as `Let` statements, so the closure
      planner's locals vector reserves the correct payload type for
      slots a `Match` arm binds. Without this, closure bodies whose
      `if let` payload binding is the only declaration site of a
      local fell back to `Unknown` → `i32` and wir_build emitted
      ref → i32 type-mismatch Wasm.
- [ ] Step 2a known gap — `mut` bindings of value-semantic
      variant payloads (e.g. `if let Some(mut s) = opt_str` where
      `S` is `String` / `Array<T>`) skip the defensive
      `$value_copy$T(...)` wrap. Pre-2a, pattern lowering emitted
      `let mut s = VariantPayload(...)` which `value_copy::insert`
      then wrapped; with the binding now living inside the Match
      arm pattern, `wir_build::pattern_match::emit_pattern_bindings`
      writes the payload directly with `local.set s =
      ref.cast(...).payload_0` and the copy is lost. Six fixtures
      regress at -O0 (`pattern_mut_binding`, `serde_sub_serializer`,
      `wasi_filesystem_advise_sync`, `wasi_filesystem_append_stream`,
      `wasi_filesystem_set_size`, `wasi_filesystem_symlink`,
      `wasi_filesystem_write_stream`). Fix candidate: in
      `lower::translate::pattern::lower`'s IfLet handler, post-
      process the Match arms — for every `mut` `Binding` whose
      local is value-semantic, lift the binding into a `Let { is_mut:
      true, ... }` at the start of the arm body and replace the
      pattern's slot with a `Wildcard` (or a fresh non-mut
      `Binding` that wir_build's `emit_pattern_bindings` can write
      into a throwaway temp). `value_copy::insert` then sees the
      explicit `Let mut` and wraps the right-hand side. The same
      fix needs to apply to user-written `match` arms in
      `lower_expr`'s Match handler; the symptom only became visible
      with IfLet → Match because user-written mut-binding fixtures
      tend to keep their match arms on integers, which Wasm copies
      by value.
- [ ] Step 2b — fully fold pattern lowering into the translator.
      Depends on Step 6 (boxing / value_copy become analysis-only),
      because `lower::translate::pattern` must currently run before
      `boxing` so address-taken `&primitive` bindings inside the
      `let s = VariantPayload(...)` chains get rewritten to
      `Box<T>` consistently with the rest of the TIR.
- [x] Step 7a — `labeled_block_fusion` recognises both consumer
      shapes:
  - Legacy `(Let { value: LabeledBlock }, If { cond: VariantTest })`
  - Canonical `(Let { value: LabeledBlock }, Expr(Match { … }))`
    The Match arm's payload binding is reused as the fused
    `__fused_payload_N` slot so the THEN body's `Local(b)` reads
    remain valid after the Match is folded into the labeled block.
    Required follow-up: `IfLet → Match` conversion in
    `lower::translate::pattern::lower` now binds the scrutinee to
    a fresh `__iflet_N` local before emitting the Match — without
    that explicit `Let`, the scrutinee was embedded directly in
    `Match.expr` and fusion never saw the `(Let, Match)` pair on
    iterator-heavy workloads (`fts` regressed ~8× C without it).
- [ ] Step 7b — remaining optimiser passes (`condition_implication`,
      `drve` / `dce` / `licm` / `sroa` / `copy_prop`) already walk
      `NirExprKind::Match` via their standard recursive visitors,
      so the Match-shape canonicalisation is transparent. Their
      variant-aware helpers (purity / aliasing) keep operating on
      `NirExprKind::Variant{Tag,Test,Payload}` because cm_binding
      and legacy synthesis still emit them; that line stays until
      Step 3 lands fully.
      Done when `mise run benchmark-all` shows no regression
      beyond the 1.50× CI threshold against the Step 1 baseline.

#### Step 3: Synthesis migration

- [x] `synthesis/traits.rs` — `Inspect`, `InspectAlt`, and `Eq`
      auto-derives for variants now emit a single (or nested,
      for `Eq`) `TirExprKind::Match` over `*self` (and `*other`)
      with one `TirMatchArm` per case. The arm's
      `TirPattern::Variant { bindings: [Binding] }` binds the
      payload to a local allocated by the generator, so the body
      reads `Local(idx)` rather than `VariantPayload(…)`. Zero
      `TirExprKind::Variant{Test,Payload}` references survive in
      `traits.rs` after the migration.
- [x] `synthesis/serde_synth.rs` — both `if_let_ok` and
      `if_let_some` helpers delegate to a shared
      `variant_match_stmt` that produces `TirStmtKind::Expr(Match)`
      with a wildcard else-arm.
- [x] `synthesis/effect_dispatch.rs` — the
      `if let Some(__d) = __saved` dispatch in the effect-handler
      wrapper now uses the canonical Match shape.
- [x] `synthesis/cm_binding/lower.rs` — all four
      memory-/flat-args-lowering synthesizers now emit canonical
      TIR `Match` with `TirPattern::Variant { bindings: [Binding] }`
      arm patterns:
  - `synthesize_lower_option_to_memory`
  - `synthesize_lower_wasi_variant_to_memory`
  - `synthesize_flatten_value_to_flat_args` (variant case)
  - `synthesize_flatten_option_to_flat_args`
    `cm_binding/lower.rs` no longer imports `if_stmt`, `block`, or
    `variant_payload`. The discriminant-byte computation still uses
    `variant_test(...)` as a 0/1 integer value (not control flow);
    that arithmetic use is held back until Step 4 settles the
    variant-value expression form.
- [ ] Remaining producers — `synthesis/cm_binding/export_adapter.rs`
      and `task_return.rs` still emit `if_stmt(variant_test(result,
      Ok), block(ok_stmts), Some(block(err_stmts)))` Result-Ok/Err
      branches with `variant_payload(...)` extraction inside both
      arms. Migration requires moving each arm's
      `let __ok_val = variant_payload(result, Ok)` into the arm's
      pattern binding — mechanical, but each call site needs the
      surrounding code restructured so the arm body reads the
      bound local instead of the extracted value. Held back until
      a follow-up patch.

  Shared helpers `synthesis::common::match_variant_test` /
  `match_variant_payload` cover the common shapes; the
  mechanical mapping is the same as the original 9.C.3
  sketch:

  - `VariantTest(v, c)` → `match v { Case(_) => true, _ => false }`
  - `VariantPayload(v, c, t)` → `match v { Case(p) => p, _ => unreachable!() }`
  - `VariantTag(v)` → `match v { Case_0 => 0, …, Case_N => N }`
  - `Switch { … }` → `Match`; `match_to_switch` re-materialises
    `Switch` for dense cases
  - `IfLet { … }` → `match scrutinee { pattern => then, _ => else }`

#### Step 4: Drop TIR variants

- [ ] Drop `TirStmtKind::IfLet` and
      `TirExprKind::{Switch, VariantTag, VariantTest, VariantPayload}`.
      Sweep consumer arms in `tir_visitor.rs`, `unparse.rs`,
      `effect_check.rs`, the remaining `synthesis/*` /
      `monomorphize/*` walkers, and `lower::translate/*`.
      `LetDestructure` stays because the resolver still emits it
      and NIR preserves the multi-value optimisation.

#### Step 5: Drop NIR variants

- [ ] Drop `NirExprKind::{VariantTag, VariantTest, VariantPayload}`.
      `NirPattern::Variant { bindings }` is the sole way to extract
      a variant payload after this lands; `wir_build::pattern_match`
      is the sole compiler of `Match` to Wasm `ref.test` + branch.

#### Step 6 (stretch): Plan sub-passes become analysis-only

- [ ] Boxing, closure, value_copy, and globals stop mutating
      `FlatPackage` and instead return analysis structs that
      `lower::translate` consumes during the fold. After this lands
      `lower::lower(flat)` is a pure TIR → NIR fold with no
      TIR-mutating pre-pass.

Subsequent work (removing the AST-level `desugar` phase) is out of
scope for this WEP. Each lands as its own follow-up.

## Consequences

### Benefits

- Type boundary at `lower`. The "lower has run" precondition is enforced statically.
- Risk concentrates on `lower`. Optimize and `wir_build` migrations are mechanical renames; the semantically interesting work stays in the smallest of the three phases.
- Enables variant trimming on both sides. With two distinct enums, variants only meaningful pre-lower can leave NIR, and variants only meaningful post-lower can leave TIR. Each trim is a small PR enforced by the type system.
- Enables removal of the AST-level `desugar` phase. Adding variants to TIR (the consequence of moving sugar elimination into `lower_tir`) does not propagate into optimize.

### Trade-offs

- Code duplication on landing. NIR's expression / statement / visitor / unparse files start as copies of TIR's. The duplication is intentional and is paid down in subsequent WEPs as the two diverge. Copying is mechanical and reviewable in one sitting.
- A short window during the transition where both `FlatPackage` and `NirPackage` flow through downstream code. The Phase 2 adapter absorbs this; Phase 5 removes it.
- One more `wado dump` mode to maintain.
