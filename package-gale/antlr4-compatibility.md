# ANTLR4 Compatibility — Stages, Test Generation, Verification

This document is the central reference for verifying that Gale stays
compatible with the upstream `antlr4` tool. It captures three things:

- **Stages** — the layers at which compatibility can be claimed,
  ordered from cheapest to most thorough.
- **Test generation** — how the descriptor-based test corpus is
  produced from `vendor/antlr4/runtime-testsuite/`.
- **Verification** — how to interpret results and triage failures.

The compatibility *contract* itself (which constructs are in scope and
which are intentionally excluded) is documented in
[`AGENTS.md` § "Compatibility Principle"](./AGENTS.md). Read that first.

## Stages of compatibility

Gale's compatibility story is layered. Higher stages depend on lower
stages already being green.

### Stage A — Syntactic compatibility (parse-only)

> **Claim:** Every well-formed `.g4` file accepted by upstream `antlr4`
> is accepted by Gale's `g4::parse` (modulo the action-body exception).

This is what the *Layer 1* and *Layer 3* tests in `AGENTS.md`
establish. It is the hard contract. Any breakage here is a Gale bug,
not a feature gap.

Two test sources cover Stage A today:

1. **Hand-curated grammars** in `tests/grammars/` (JSON, SQLite,
   CSS3, HTML, ANTLR4, Rust, TypeScript, …). Driven by
   `g4/integration_test.wado`.
2. **Upstream descriptor corpus** at
   `vendor/antlr4/runtime-testsuite/resources/.../descriptors/`,
   extracted into `tests/antlr4_descriptors/<Category>/<Name>.g4`
   and exercised by per-category `tests/antlr4_descriptor_*_test.wado`.

### Stage B — Semantic compatibility (codegen + parse-tree shape)

> **Claim:** A parser generated by Gale from a `.g4` produces, for the
> same input, an `to_string_tree()` output equal to the one ANTLR4
> would produce.

This is partially established by *Driver Tests* (`AGENTS.md` §
"Driver Tests: S-expression Tree Assertions"): each driver fixture
has a hand-written set of `(input, expected tree)` cases. The same
machinery applies to descriptor-based fixtures — the descriptor's
`[input]` and a normalised form of `[output]` can drive automated
equivalence checks where the descriptor is "clean" (no host-language
action printing).

Stage B is *partial today*: only the curated driver fixtures
participate. Lifting descriptor-based fixtures into Stage B is
[Phase 3 below](#phase-3--stage-b-tree-shape-equivalence).

### Stage C — Action-body translation (out of scope)

Translating host-language `{ … }` bodies — `@header`, `@members`,
inline actions, `{ … }?` semantic predicates, `catch`/`finally`
bodies — would let Gale execute predicate-gated alternatives and
host-language side effects exactly as ANTLR4 does. This requires a
cross-language translator (Java/Python/TypeScript/Rust → Wado) and
is explicitly **deferred** per `AGENTS.md` § "Future Work" and
`docs/wep-2026-03-02-gale.md`. There is no plan to land Stage C in
the short term.

## The descriptor pipeline (Stage A automation)

Upstream `antlr4` ships a JUnit-driven runtime test suite at
`vendor/antlr4/runtime-testsuite/`. Each `.txt` descriptor under
`resources/org/antlr/v4/test/runtime/descriptors/<Category>/` carries
a `[grammar]` block (a real `.g4`), an optional `[input]`, an
optional `[output]`, and a few flags. The format is documented in
`vendor/antlr4/runtime-testsuite/test/.../RuntimeTestDescriptorParser.java`.

The descriptor pipeline turns these into Gale parse-only tests.

### Pipeline diagram

```
vendor/antlr4/.../descriptors/<Category>/<Name>.txt
                  │
                  ▼
   scripts/extract_antlr4_descriptors.wado
   (reads [grammar] / [slaveGrammar], applies trim /
    triple-quote / trailing-newline rules from Java's
    RuntimeTestDescriptorParser.parse, mirrors them to disk)
                  │
                  ▼
tests/antlr4_descriptors/<Category>/<Name>.g4   (extracted grammar)
tests/antlr4_descriptor_<category>_test.wado    (one test per descriptor)
                  │              │
                  │              └── consults tests/antlr4_descriptors_status.toml
                  │                  to decorate todo / skip entries
                  ▼
        wado test  (runs the generated tests through the
                    standard Wado test harness)
```

The Wado script is self-contained: no `wado.toml`, no kiln, no
imports from `package-gale/src`. It only uses `wadopoet::CodeWriter`
to emit Wado source, plus `core:cli` and `wasi:filesystem` for I/O.

### Files

| Path | Role |
|---|---|
| `scripts/extract_antlr4_descriptors.wado` | Extractor (single-file Wado script) |
| `scripts/extract-antlr4-descriptors.sh` | Wrapper resolving the category list and forwarding to `wado run` |
| `tests/antlr4_descriptors/` | Generated `.g4` files (committed) |
| `tests/antlr4_descriptor_*_test.wado` | Generated tests (committed) |
| `tests/antlr4_descriptors_status.toml` | Manually maintained triage state |

### Triage states (`antlr4_descriptors_status.toml`)

```toml
[todo]
"<Category>/<Name>" = "one-line reason a real Gale gap blocks this"

[skip]
"<Category>/<Name>" = "one-line reason this descriptor isn't a real .g4"
```

| State | Effect | When to use |
|---|---|---|
| (default) | Test runs, must pass | Descriptor is a clean ANTLR4 grammar Gale should accept |
| `[todo]` | Test marked `#[TODO]` so failure is expected and recorded | Descriptor exposes a real Gale gap (parser, lexer, or IR feature). Add a corresponding entry to `TODO.md` |
| `[skip]` | Test not emitted at all | Descriptor relies on the upstream test runner's StringTemplate substitution / target-language template, so it is not a self-contained `.g4` |

The reason text is written verbatim into the generated test as a
comment. Keep it free of backslashes and double quotes — the script's
TOML parser is intentionally minimal and does not unescape strings.

## Generating tests

Initialize the submodule the first time you work on this:

```sh
git submodule update --init --recommend-shallow vendor/antlr4
```

Re-generate after editing `status.toml`, after adding categories, or
after bumping `vendor/antlr4`:

```sh
# Default: Phase 1 set (Sets, LexerExec, ParseTrees)
package-gale/scripts/extract-antlr4-descriptors.sh

# A specific subset
package-gale/scripts/extract-antlr4-descriptors.sh ParserExec LeftRecursion

# Every category present under .../descriptors/
package-gale/scripts/extract-antlr4-descriptors.sh all
```

The wrapper changes `cwd` to the repository root and runs the Wado
script via `cargo run --bin wado -- run`, with the cwd preopen.
Generated `.g4` and `.wado` files go directly under
`package-gale/tests/`.

The pipeline is **manually re-run**, not a CI step. Generated
artefacts are committed; CI just runs `wado test` on the existing
fixtures.

If `vendor/antlr4/` is missing, the script aborts with instructions
for `git submodule update --init …` and never auto-initialises.

## Verification & triage

### Running the generated tests

```sh
# All descriptor-based tests
wado test package-gale/tests/antlr4_descriptor_*_test.wado

# A single category
wado test package-gale/tests/antlr4_descriptor_lexer_exec_test.wado
```

Output for a healthy run looks like:

```
... (76 lines of `ok`)

TODO tests (7):
  · pending   ... — sets_unicodeescapedbmprangeset
  · pending   ... — sets_unicodeescapedsmprangeset
  · pending   ... — lexerexec_nongreedyoptional
  ... (etc)

76 passed, 0 failed; 7 todo
```

`#[TODO]` tests intentionally fail; the runner counts them on a
separate axis from `failed`. A `#[TODO]` that *passes* is a build
break — it means the underlying gap was closed and the entry should
be removed from `status.toml`.

### Triaging a new failure

When the descriptor extractor surfaces a previously-unseen failure:

1. **Read the descriptor's `.txt` upstream** to confirm what it is
   testing. Look for unsubstituted `<Template>` directives at grammar
   level — those are testsuite-only, not real `.g4`, and belong in
   `[skip]`.
2. **Reproduce locally** to confirm Gale's parse error:
   `wado run package-gale -- dump tests/antlr4_descriptors/<Category>/<Name>.g4`.
3. **Decide on the bucket:**
   - Real Gale gap → `[todo]` with a one-line reason. Mirror the gap
     in `TODO.md` so it is tracked alongside the existing gaps.
   - Testsuite-template artefact → `[skip]` with the reason.
   - Genuine compiler bug surfaced en route → write a minimum
     reproducible fixture under `wado-compiler/tests/fixtures/`
     **before** marking the descriptor (per CLAUDE.md project rule).
4. **Re-run the wrapper** so the generated test picks up the new
   triage state.

### When closing a gap

Once a Gale gap is fixed:

1. Run `package-gale/scripts/extract-antlr4-descriptors.sh` again to
   regenerate the test files (the `#[TODO]` decoration disappears
   automatically once the entry is removed from `status.toml`).
2. Remove the entry from `status.toml` and from `TODO.md`.
3. The previously-`#[TODO]` test must now pass.

## Current state

### Phase 1 (landed) — Sets, LexerExec, ParseTrees

- 83 descriptors extracted, 76 pass, 7 marked `#[TODO]`.

The 7 `#[TODO]` items are real Gale gaps:

| Category / Descriptor | Gap |
|---|---|
| `Sets/UnicodeEscapedBMPRangeSet` | Testsuite double-backslash unicode escape (`'\\u{…}'`) is not unwrapped before ANTLR-style parsing |
| `Sets/UnicodeEscapedSMPRangeSet` | Same — supplementary plane variant |
| `Sets/UnicodeEscapedSMPRangeSetMismatch` | Same |
| `Sets/UnicodeNegatedSMPSetIncludesBMPCodePoints` | Same |
| `LexerExec/NonGreedyOptional` | Parser does not recognise `??` non-greedy optional on a single element (`*?` and `+?` are handled) |
| `ParseTrees/AltNum` | Grammar-level `<…>` StringTemplate directive that the upstream test runner substitutes per target before compilation |
| `ParseTrees/TokenAndRuleContextString` | Same shape as above |

### Phase 2 (planned) — `ParserExec`, `LeftRecursion`, `SemPred*`, `Composite*`, `FullContextParsing`, `*Errors`

Remaining categories under `vendor/antlr4/.../descriptors/`. Run the
extractor with `all` (or specific categories) once Phase 1 stabilises;
new failures triage into `status.toml` the same way.

`LeftRecursion` (98 descriptors) deserves special attention — Gale's
left-recursion handling is documented in
[`docs/wep-2026-03-02-gale.md`](../docs/wep-2026-03-02-gale.md) and
in the "Failed Approaches" section of `AGENTS.md`. Many `[todo]`
entries are likely there.

### Phase 3 — Stage B tree-shape equivalence

Once descriptors are accepted by `g4::parse`, the natural next step
is to feed the `[input]` blocks through the *generated* parser and
check `to_string_tree()` against a normalised form of `[output]`.
Mechanically this is the same machinery as the existing driver
fixtures, but driven systematically off the descriptor corpus
instead of hand-written cases.

This requires:

1. A second extractor pass that emits, for each `[output]`-bearing
   descriptor, a Wado driver test (`use ... with { generator: ... }`)
   with `assert_tree(input, expected)`.
2. A normaliser that strips the `[output]`'s host-language
   side-effect prints (e.g. `<writeln(...)>` outputs) and keeps only
   the parse-tree shape.
3. Triage entries like `[stage_b_skip]` for descriptors whose
   `[output]` is *only* host-language prints (no observable tree
   structure).

There is no Stage B descriptor automation today; only Phase 1's
parse-only layer is wired.

## Compiler bugs surfaced during compatibility work

Pursuing the descriptor corpus has shaken out compiler bugs that
unrelated test paths missed. Both have landed in this branch with
regression fixtures under `wado-compiler/tests/fixtures/`:

- **`null` arm in `match` / `if`** —
  `match_null_arm_infers_option_inner.wado`. `Literal::Null` was
  initially typed as `Option<UNKNOWN>` and never re-resolved when a
  sibling arm produced `Option::Some(s)`. Fixed in
  `wado-compiler/src/resolver/expr.rs`.
- **Generic-instance fq collision on same-named CM types** —
  `result_unit_cm_variant_passthrough.wado`. `mangle_type_name` was
  not type-id-injective: `wasi:filesystem`'s `pub variant ErrorCode`
  and `wasi:cli`'s `pub enum ErrorCode` collapsed onto the same WIR
  fq, so `register_mono_variants` could register the wrong payload
  representation depending on entry-filename order. Fixed by
  introducing `TypeTable::mangle_type_arg_for_generic` and threading
  it through the WIR layer's generic-instance fq computation.

When Phase 2/3 surface further compiler bugs, follow the project
rule from the top-level `CLAUDE.md`: write a minimum reproducible
fixture first, fix the underlying compiler issue, *then* update the
descriptor triage.
